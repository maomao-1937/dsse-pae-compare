# Research notes

DSSE uses a length-framed byte string to bind payload type and body. The protocol requires UTF-8 bytes for the type and allows two base64 alphabets in the JSON envelope. A Sigstore JavaScript advisory describes a historical implementation that truncated UTF-16 code units to low bytes and counted code units in its type-length prefix. This tool makes the difference visible using small explicit fixtures. [DSSE protocol](https://github.com/secure-systems-lab/dsse/blob/master/protocol.md), [JSON envelope](https://github.com/secure-systems-lab/dsse/blob/master/envelope.md), [Sigstore advisory](https://github.com/sigstore/sigstore-js/security/advisories/GHSA-jfc7-64v2-mr8c).

The upstream reference vector demonstrates the intended byte layout for a single case. A Sigstore or in-toto verifier uses the signing input with actual signatures and trust material. This CLI instead compares two inputs and reports whether the specific historical model collapses a difference. The scope is fixture diagnostics. [Reference vector](https://github.com/secure-systems-lab/dsse/blob/master/protocol.md#test-vectors), [Sigstore client specification](https://github.com/sigstore/architecture-docs/blob/main/client-spec.md).
